## 2026-03-30 - Form Controls Property Collision when Restoring LocalStorage Drafts
**Vulnerability:** Accessing form elements directly via property access `form.elements[key]` when populating fields from untrusted or persisted draft data (`localStorage`) collides with built-in properties/methods of `HTMLFormControlsCollection` (such as `length`, `item`, `namedItem`, `toString`, `reset`, `submit`). In strict mode (ES modules), trying to set `.value` on function or primitive properties throws a `TypeError`, breaking draft restoration and potentially crashing form state handling.
**Learning:** HTML form collections expose both form input elements and collection prototype properties on the same object interface. Direct string indexing (`form.elements[key]`) cannot differentiate between an input named `key` and a collection property/method named `key`.
**Prevention:** Always use `form.elements.namedItem(key)` to look up form inputs safely by name without triggering prototype property lookup or collision.
